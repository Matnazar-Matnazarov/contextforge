# Security model

This is a local portfolio application. It has had no external security review and is **not** claimed production-ready.

## Authentication and CSRF

Django session cookies (HttpOnly, SameSite=Lax; `Secure` when `DJANGO_SECURE_COOKIES=1`). No tokens in `localStorage`.
Caddy serves UI and API on one origin, so CORS is closed by default. All unsafe API requests need the `X-CSRFToken` header
(the SPA fetches `/api/auth/csrf/` and echoes the cookie). Login/register and chat/upload endpoints are rate-limited (DRF scoped throttles).
Passwords use Django's hashers and validators (min length 10, common-password and similarity checks).

## Roles and permission matrix

| Action | Owner | Admin | Member |
|---|:-:|:-:|:-:|
| View organization and member list | ✔ | ✔ | ✔ |
| Rename / delete organization | ✔ | ✘ | ✘ |
| Add member with role `member` | ✔ | ✔ | ✘ |
| Add admin/owner, change any role | ✔ | ✘ | ✘ |
| Remove a `member` | ✔ | ✔ | ✘ |
| Remove an admin or owner | ✔ | ✘ | ✘ |
| Upload, list, download documents | ✔ | ✔ | ✔ |
| Delete / re-index any document | ✔ | ✔ | ✘ |
| Delete / re-index own uploads | ✔ | ✔ | ✔ |
| Create conversations, ask questions | ✔ | ✔ | ✔ |
| Read another user's conversation | ✘ | ✘ | ✘ |

The last organization owner cannot be demoted or removed. The matrix is implemented in `apps/organizations/permissions.py` and exercised by `tests/test_organizations.py`.
Members are added by email and must already have an account (no invitation e-mail flow).

## Tenant isolation: layers

1. **Org context** (`OrgContextMixin`): every org-scoped route has `org_id` in the URL. It is accepted only if the authenticated user has an *active* membership; otherwise the response is 404 (indistinguishable from "does not exist").
2. **Scoped queries**: every object lookup includes the validated organization (`Document.objects.filter(pk=…, organization=org)`); a foreign id behaves as missing.
3. **Conversations** additionally require `owner = request.user`.
4. **Qdrant**: `search`/`delete_document` require an organization id and always add it to the filter; ids come from membership, not request payloads.
5. **DB re-validation of hits** (document exists, same org, `indexed`).
6. **Citation validation** against the request's retrieved chunks.
7. **Background jobs** receive only a document id; org, object key and filename are read from the DB, and the object key must start with `orgs/{document.organization_id}/`.
8. **Storage**: bucket is private; the browser never sees a storage URL or credential. Downloads are streamed by Django after authorization with `Content-Disposition: attachment`, `nosniff`, `no-store`.

## Upload safety

Extension allow-list, size cap (Django, Caddy), libmagic content check, UTF-8 check, SHA-256 duplicate detection per organization, generated object keys (filename never used in a path), PDF page cap, encrypted PDFs rejected.
Parsing runs in the worker process; a malicious PDF could still exploit a parser bug. Sandboxing the worker is future work.

## Prompt injection and hallucination

Retrieved text and chat history are untrusted. Mitigations: explicit system instructions, delimiter escaping, JSON-only output, the LLM never decides authorization (that is plain code and SQL/Qdrant filters),
and citations are validated server-side. The model can still be manipulated into a misleading *answer text* from injected content or can paraphrase incorrectly;
users should check cited excerpts. Answers without verifiable citations are replaced with the insufficient-context message.

## Data sent to Google

When a question is answered, **the question, up to three short prior chat turns, and the retrieved document excerpts (≤ `RAG_MAX_CONTEXT_CHARS`) are sent to the Gemini API.**
Embeddings are computed locally and original files never leave your machine. Do not index data you are not allowed to send to Google. Review Google's API terms for retention and
training policy for your key type. The system is therefore *not* fully private or offline.

## Secrets and logging

Secrets come from `.env` (git-ignored, generated by `make env`). Logs record ids, sizes, status codes and exception types; never file contents, prompts, answers, passwords or keys. Error responses use a fixed envelope and hide exception text.

## Known gaps

No MFA, email verification, password reset, account lockout beyond rate limits, audit log, virus scanning, OCR, per-document ACLs, HTTPS (local HTTP only), or automatic orphan-object sweeping.
